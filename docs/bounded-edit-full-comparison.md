# Bounded-edit full development comparison protocol

Freeze the current source before a fresh baseline/treatment comparison of all
34 inspected retail tasks in `data/heldout2/selected_tasks`, with their existing
annotations. These remain development data, never untouched confirmation.

Variants: baseline and safeguard-transaction. Seed index: 0. Workers: 2.
Existing gpt-5.4-1 deployment for agent and simulator; unchanged 20-turn budget.
Expected cells: 68 valid trajectories, 34 complete pairs. Run:
`outputs/runs/transaction-bounded-edit-full-development/`.

Latest treatment includes bounded address prerequisites, independent explicit
affirmative instructions, recognized color-only edits and controlled exact
manifest assent. It does not change rewards, termination criteria, annotations,
simulator goals, original benchmark files, or the baseline implementation.

Verify frozen source hashes, complete unique cell coverage and stored original
rewards before analysis. Use the existing statistics, attribution and overhead
scripts unchanged. Report full task success, effective non-gold-write
trajectories/counts, missed gold writes and applicable commission denominator.
Keep all valid failures; infrastructure errors, if any, must be separately
identified, not silently substituted. Never pool versions.

The goal is to assess descriptive development behavior after repairs, not
declare significance from selected recoveries. Report confidence intervals
and task/Holm p-values even if results are unfavorable. No utility
non-inferiority or general safety claim follows from a non-significant test.
